# NFSP-style hidden-information self-play baseline

`train_nfsp50.py` is the first equilibrium-oriented training baseline on top of the GPU-resident Torch50 environment. It keeps the existing Monte-Carlo actor-critic trainer intact so the new algorithm can be measured independently.

This is an **NFSP-style anticipatory fictitious-self-play baseline**, not a claim that the actor-critic best-response learner is identical to the DQN learner used in the original NFSP paper. The important structural properties are present:

1. each player independently chooses its behavior policy once per game,
2. with probability `--anticipatory` it uses the current best-response (BR) policy,
3. otherwise it uses a learned historical average policy,
4. only decisions actually generated by the BR behavior enter the BR training replay,
5. the same BR state/action examples enter an Algorithm-R reservoir,
6. the average policy is trained by supervised cross-entropy from that reservoir.

The public Torch50 observation remains the information state. Opponent hand identities and stock identities are not exposed to either network.

## Why a reservoir matters

A circular replay would represent only a recent moving window and would not approximate the historical average strategy required by fictitious play. `PackedGpuReservoirBuffer` therefore uses Algorithm R. Before capacity is reached every BR example is retained. Afterwards each incoming stream item draws a replacement slot with the standard `capacity / items_seen` retention probability.

Reservoir rows use the same 137-byte packed Torch50 representation as the existing replay. Batched replacement collisions are resolved by retaining the latest incoming row for each destination slot, matching sequential Algorithm-R replacement order for the generated draws.

## Default RTX 5080 configuration

The default configuration is intentionally conservative for a 16 GiB RTX 5080:

- self-play batch: `131072` games,
- anticipatory parameter: `0.10`,
- BR-only trajectory: `1048576` transitions,
- BR ring replay: `4194304` transitions (~548 MiB),
- average-policy reservoir: `16777216` transitions (~2192 MiB),
- BR updates per iteration: `64`,
- average-policy updates per iteration: `64`,
- training minibatch: `4096`,
- CUDA AMP enabled.

With eta=0.10, only about one tenth of decision rows are expected to enter the BR-only trajectory. The trajectory is therefore much smaller than the full-rollout trajectory used by `train50.py` while still leaving substantial headroom for policy changes.

## Commands

Short validation run:

```powershell
.\.venv-torch\Scripts\python.exe python\train_nfsp50.py --iterations 3 --selfplay-batch 32768 --br-updates-per-iter 8 --average-updates-per-iter 8
```

Default training:

```powershell
.\.venv-torch\Scripts\python.exe python\train_nfsp50.py --iterations 1000 --checkpoint-every 25
```

The deploy/evaluation policy for NFSP is the **average policy**, not the BR policy. The BR policy exists to generate improving responses to the average strategy.

## Next algorithmic step

Torch50 states are trivially copyable GPU byte rows. After this anticipatory/average-policy pipeline is validated, the next stronger target is batched external-sampling CFR / Deep CFR. That requires an explicit GPU branch/clone API and batched traverser-action expansion so counterfactual action values can be generated without Python-recursive state explosion.
